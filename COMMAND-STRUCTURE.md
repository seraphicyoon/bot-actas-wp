# Reorganización de comandos — fase 1
Registro central de categorías en command-router.js, menús contextuales en command-menus.js. Se conservan los handlers de pagos, entregas, inventarios, rentas, stickers, videos, moderación y bienvenidas. La ruta antigua queda como respaldo para operaciones de trámites/proveedor que no se han migrado. No se elimina ni modifica ningún dato. Los grupos autorizados sin modo explícito conservan compatibilidad anterior; no se migran automáticamente. .modo identifica el contexto; .ayuda, .comandos y .ayudatienda muestran comandos por chat/rol; .jinni continúa exclusiva para owners. .abrir/.cerrar/.n funcionan sin modo de ventas. Stock privado exige dueño; las operaciones de tienda no se enrutan a trámites. La guía no constituye una nueva autorización; los handlers existentes verifican permisos. El instalador comprueba anclas y archivos locales, respalda antes de escribir, no ejecuta git pull ni reinicia. La comprobación puede rechazar help-handler.js si el VPS contiene cambios locales: revisar y adaptar en lugar de sobrescribir. Pruebas de enrutamiento simuladas y casos de integración agregados; ejecutar npm test en copia aislada, no directamente en proceso activo.
